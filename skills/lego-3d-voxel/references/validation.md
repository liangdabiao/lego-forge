# 验收清单

顺序不能颠倒：**先验数据，再验装配，最后验观感**。数据错了后面的都白看。

下文 `<skill>` = 本 skill 目录（`scripts/` 就在它下面），不依赖外部工程。

## 第 0 关：球测试（第一次用这条管线时必做）

```bash
python <skill>/scripts/vox.py --glb dummy --out <work>/ball.json --ball
# 配 scripts/build.mjs → 走宿主的 build 检查（没有就只看切片）
```

24 层、每层一色。判读：

- 球是圆的（不是方的、不是半球的）→ 网格与切片坐标对；
- 每层颜色清晰分成 24 个横带（不是竖条纹、不是斜纹）→ 层的方向对、`y = 层 * 3` 对；
- 装配报告 PASS → 打包链路对。

球错了就停下修管线，不要带着错误管线去做人像。
**球对了不代表人像对**：球是凸体，看不出"按列填实"和"空腔"的问题（见 `pitfalls.md` 第 3 条）。

## 第 1 关：切片数据（build 之前）

```bash
python <skill>/scripts/preview.py --vol <work>/volume.json --outdir <work>
```

看三张正交视图 + `layers.png`：

| 检查项 | 通过 | 不通过说明 |
|---|---|---|
| 正视图轮廓 | 与模型一致，能认出人脸/姿态 | 轮廓糊、变方 → 层数不够或网格比例错 |
| 侧面/背面 | 有厚度、不是纸片 | 一片平 → 深度轴没切，或 stride 读错 |
| 悬垂下方 | 能透出白底（空的） | 实心 → 按列填实，回去改洪泛 |
| 颜色分区 | 成片：脸肤色、袍子一色、眉眼深色 | 斑驳/整体单色 → 查 UV 翻转、方向仓、数值量级 |
| 分层图 | 每层轮廓逐层变化 | 每层形状一样 → 被填成柱子了 |

**脸部一定要单独凑近看**（这是漏掉最多的一关，`hero.png` 缩小后看不出问题）：

| 检查项 | 通过 | 不通过说明 |
|---|---|---|
| 眉毛 | 两条深色，左右分开 | 与眼睛连成一坨 → 层数不够 |
| **眼睛** | **眉下有一条独立的深色弧线，和眉毛之间隔着肤色** | 完全消失 → 先查 carve 是否生效、`--darkdetail` 是否被关；两处都开了还没有，就是**未解决**的遗留问题（`pitfalls.md` 6b） |
| 胡须/嘴 | 深色块边界清楚，里面没有杂色点 | 里面有红点 → 归并/吸收没开 |

**这一关必须真看像素**，不能靠"参数都开上了"推断。用 `scripts/probe.py --layers/--cols` 打正面 ASCII 色图
是最快的判定方式：眼睛应该在眉下方 1~3 层、左右对称各出现一条。ASCII 里那一带全是肤色，就是没有眼睛。

这一步花 30 秒，能省掉一整轮"build 完发现全错"。

## 第 2 关：装配

```bash
node <宿主工具链>/bin/lego.mjs build <name>     # 宿主工程有这套工具才需要
head -5 <work>/out/report.txt
```

必须：**`PASS` + `0 errors`**。

- `0 errors` 之外还要看 `parts by kind`：体素塑像应该是 100% brick，`0.00 plates per brick` 是正常现象
  （每格一颗 1×1×3 砖），不要按普通街景套装的 1.13 去要求它。
- 出现 `not connected` → 见 `pitfalls.md` 第 7 条（底部外沿换色断连），本管线目前的已知薄弱点，
  128 层实测 503 处。

## 第 3 关：观感

```bash
node <宿主工具链>/bin/lego.mjs shots <name>     # 或用自己的渲染器看 volume.json
```

看六视图和主图：
- 六视图里没有一个角度"塌成一片"；
- 颜色在渲染后没有变成意外的粉/灰（某些色在渲染器里偏色，例如 `Orange` 偏粉）；
- 与参考照片/模型并排比对，轮廓与主要色块对得上。

**这一关必须由用户拍板**。造型、配色属于用户判断；自己连续改三版再交付，通常三版方向都错。
每完成一版就先给用户看，等确认再动下一版。

## 已知薄弱点（交付时要主动说明）

1. **连接**：底部外沿换色断连，128 层是 503 处量级（见 `pitfalls.md` 第 7 条）。模型能拼但会散，**未解决**。
2. **极细结构**（手指、飘带、流苏）在 7.8 mm 层高下必然丢失，属于物理上限，不是 bug。
3. **扫描件的成片脏区**：按区域归并能治，但如果脏区和真花纹混在一起（例如底座纹样），
   归并会把它一起抹平——那种情况要手工决定"保花纹还是保干净"。
